# Access authentication contract

Schema2 adds optional `auth.basic={profile:"basic-<revision>-<time>"}` globally.
There is no global authentication mode. Each site has `auth={mode:"none"}` or
`auth={mode:"basic",source:"global"}` or
`auth={mode:"basic",source:"independent",profile:"basic-..."}`.
Missing site auth means none. Ticket08 extends global `auth` with `authelia`
parameters and site mode with `authelia`, preserving this reference contract.

`basic_profile_save({scope,config,users,expected_revision})` requires write ACL.
Scope is `global` or an existing site's domain. Config is the editor's entire
configuration (or omitted to use saved draft). This saves all current editor
changes and creates a new draft revision, never applies. Each account contains
`username` and exactly one of `password`, `hash`, or `retain:true`.
An omitted/removed account is deleted; retain only matches a prior username in
that scope's profile. Passwords cross a private stdin pipe to actual Caddy's
`hash-password --algorithm bcrypt`; no plaintext file or process argument is
created. Passwords accept1–72bytes and exclude CR/LF/NUL. Existing advanced
hash input accepts bcrypt cost4–16. Hashes never leave the manager via RPC,
including writer `draft_edit`, preview, mutation responses and errors.

Private mode0600 immutable `basic` sections in `/etc/config/caddy_secrets`
contain ordered `list username` and `list hash` fields. The package has no public
LuCI UCI ACL; legacy JSON files are migration inputs only. Public drafts contain
only references. Old versions are retained for last-active/recovery stability;
this ticket does not garbage-collect profiles. Saving never rewrites an active
profile. A failed validate/load therefore retains old credentials, including
service restart/reload from durable active.json. Generated active/candidate JSON
necessarily contains hashes and remains private; generated preview substitutes
`[private hash]`. No export method reads active/candidate JSON.

State adds `basic_profiles` (reference -> username metadata only) and
`affected_domains` (global Basic Auth references when draft differs from active).
The native page displays affected domains before Apply. Global reference is
resolved while compiling the draft, so all referencing sites change together;
independent profiles remain unchanged. Authentication executes inside the
matching path route before advanced snippets, prefix stripping and proxy.
Unmatched paths return404 without an authentication challenge.

Manual source retains form profiles but never resolves or applies them;
account mutation is refused and native account/content forms are disabled.
Service actions remain independent.

## Authelia forward authorization (ticket08)

Global `auth.authelia={backend,uri,portal}` contains public connection parameters,
not usernames, passwords, cookies or tokens. Backend is a router-reachable
HTTP(S) authority with explicit port and no URL credentials, path or query.
`uri` is an absolute authorization path; default UI value is the modern
`/api/authz/forward-auth`. `portal` is the HTTP(S) login URL without credentials,
query or fragment. URI query overrides are generated by URL-encoding portal
into `authelia_url`. HTTPS auth backends retain certificate verification.

Sites choose `auth={mode:"authelia",source:"global"}` (dynamic reference) or
`auth={mode:"authelia",source:"independent",authelia:{backend,uri,portal}}`.
Global Basic and Authelia parameters coexist and do not select a default mode.
State `affected_domains` includes only sites referencing a changed global
Basic profile or Authelia parameter set relative to last active configuration.
Native Save & Apply saves first and presents those domains before actual load.
Independent parameters remain unchanged when global parameters change.

Inside the matching path, before snippets or prefix stripping, request identity
headers Remote-User/Groups/Email/Name are deleted. The authorization proxy makes
GET without consuming the original body, explicitly forwards original method
and URI plus normal Caddy forwarded metadata, and copies the four allowlisted
response attributes only on2xx. Missing attributes remain absent. Other auth
responses retain their status/Location; unreachable auth returns502 and never
reaches the application. No arbitrary client forwarded-proxy ranges are trusted.
Unmatched paths still return404 without reaching authorization.

A configured portal hostname/path covered by an authenticated managed site is
rejected with setup guidance to avoid a login loop. The portal must select none;
external Authelia owns users, MFA, session cookie domain/authelia_url, access
policies and routing reachability. Apply validates configuration and hot loads;
it does not promise backend health or user login success. The real request
fixture separately verifies those behaviors. The plugin does not manage uhttpd,
router DNS/firewall/NAT, OS trust stores or external Authelia configuration.
